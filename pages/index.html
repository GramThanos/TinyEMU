TinyEMU

Linux on x86 and RISC‑V, in your browser

A small system emulator that boots real Linux distributions, natively or as WebAssembly. A from-scratch 32-bit x86 CPU with an x86 → WASM JIT, RISC-V RV32/64/128, VirtIO devices and disks streamed over HTTP.

Boot Linux in the browser Download View on GitHub
🖥️

Two machines, one engine

A PC with a 32-bit protected-mode x86 CPU (x87, SSE/SSE2) and a RISC-V machine (RV32/64/128 IMAFDQC), sharing the same device layer.

🐧

Boots real Linux

Alpine and Debian on i686, Linux 6.12 on riscv64 through OpenSBI. Kernels load directly, with no BIOS; gzip bzImages are inflated on the host.

⚡

x86 → WebAssembly JIT

Hot guest code pages compile into WASM functions in the background while the interpreter keeps running. Boots Alpine in about 10 seconds.

🌐

Disks over HTTP

Block devices stream in chunks (raw or gzip) and 9P filesystems load on demand, so a multi-GB image boots after downloading only what it reads.

🧩

VirtIO everything

Console, block, network (user-mode SLIRP natively), 9P, input and a simple framebuffer, described by a short JSON config.

📦

Native too, MIT licensed

temu builds for Linux (software CPU or KVM) and Windows. Based on Fabrice Bellard's TinyEMU, MIT like the original.

Try it in your browser

Pick an image from TinyEMU-distros and boot it. The engine runs in a web worker on this page; the kernel and the disk chunks it reads are fetched from GitHub Pages. The lite images skip init and drop straight into a root shell.

TinyEMU

Downloads a few MB of kernel and disk. Needs a browser with WebAssembly exception handling (Chrome 95+, Safari 15.4+, Firefox 131+).

A lite image runs the shell as init, so mount /proc before using free or ps. The guest has no network here. Its clock starts at boot time on x86; the RISC-V machine has no RTC, so it starts in 1970.

Getting Started

Linux

sh
curl -LO https://gramthanos.github.io/TinyEMU/bin/<version>/temu-linux-x86_64.tar.gz
tar xzf temu-linux-x86_64.tar.gz
./temu-soft https://gramthanos.github.io/TinyEMU-distros/alpine-3.20-x86-lite/config.cfg

temu-soft has the software x86 CPU and RISC-V, with HTTP disks, user-mode networking and an SDL window for framebuffer guests. temu-kvm runs the PC machine through KVM (needs /dev/kvm).

Windows

powershell
Invoke-WebRequest https://gramthanos.github.io/TinyEMU/bin/<version>/temu-windows.zip -OutFile temu-windows.zip
Expand-Archive temu-windows.zip temu
.\temu\temu.exe https://gramthanos.github.io/TinyEMU-distros/alpine-3.20-x86-lite/config.cfg

The Windows build is headless (console only), with HTTP disks and user-mode networking.

TIPThe VirtIO console hvc0 is the one that takes keyboard input, so guests should use console=hvc0. The config may also be a local file or a data: URL.

A config

A VM is a small JSON5-style file. Paths are relative to the config:

cfg
{
  version: 1,
  machine: "pc",                 // or "riscv32", "riscv64", "riscv128"
  memory_size: 128,              // MB
  bios: "fw_jump.bin",           // RISC-V: OpenSBI; the PC has no BIOS
  kernel: "kernel.bin",          // bzImage (gzip inflated on the host) or ELF
  cmdline: "console=hvc0 root=/dev/vda rw",
  drive0: { file: "blk.txt" },   // chunked HTTP disk, or a raw image
  fs0: { file: "rootfs", tag: "/dev/root" },  // 9P filesystem
  eth0: { driver: "user" },      // SLIRP natively; the host's network in the browser
  display0: { device: "simplefb", width: 800, height: 600 },
}

The WebAssembly engine

x86emu-wasm.js and x86emu-wasm.wasm are one engine with both machines (the name is historical). Load them from here with a pinned version rather than engine/latest/, since a release may change the engine's JS API:

url
https://gramthanos.github.io/TinyEMU/engine/<version>/x86emu-wasm.js
https://gramthanos.github.io/TinyEMU/engine/<version>/x86emu-wasm.wasm

With jsLab

jsLab is the runtime that drives the engine in a page: several VMs, volumes, snapshots and a virtual network between them.

js
import { VMManager } from './jsLab/lib/vm/index.js';

const vms = new VMManager({ urls: {
  wasmJsUrl:  'https://gramthanos.github.io/TinyEMU/engine/<version>/x86emu-wasm.js',
  wasmBinUrl: 'https://gramthanos.github.io/TinyEMU/engine/<version>/x86emu-wasm.wasm',
} });

Driving it yourself

The engine is a classic Emscripten script that reads a global Module. Give it a console, an XHR table, then call vm_start. This is all the playground above does, in a worker:

js
self.Module = {
  locateFile: (f) => engineBase + f,          // where the .wasm is
  x86jit: true,                                 // turn on the x86 JIT
  api: {
    terminal: {
      write: (bytes) => term.write(bytes.slice()), // console output
      getSize: () => [80, 25],
    },
    wgetRequests: { n: 1, new(x) { return this.n++; }, remove() {} },
    downloading: { update(flag) {} },
  },
  onRuntimeInitialized() {
    Module.ccall('vm_start', null,
      ['string', 'number', 'string', 'string', 'number', 'number', 'number'],
      [configUrl, 0 /* RAM: from config */, '' /* cmdline */, null,
       0, 0 /* no framebuffer */, 0 /* no network */]);
  },
};
importScripts(engineUrl);

// keyboard input, one byte at a time
for (const b of new TextEncoder().encode(text)) Module._console_queue_char(b);
ExportUse
vm_start(url, ramMB, cmdline, pwd, width, height, net)load a config (http(s):, data: or blob:) and boot it; width/height > 0 adds a framebuffer drawn through Module.api.display
vm_pause, vm_resume, vm_stopcontrol the run loop
console_queue_char(c)console input
display_key_event, display_mouse_event, display_wheel_eventframebuffer input (VirtIO input)

vm_snapshot_clock, vm_reserve_memory, vm_restoresnapshots: save the whole WASM memory between ticks, restore into a fresh instance

Building from source

Docker is the supported path; the image has every native and Windows cross-build dependency.

sh
git clone https://github.com/GramThanos/TinyEMU && cd TinyEMU
docker compose build build
docker compose run --rm build              # release binaries into dist/
docker run --rm -v "$PWD":/src -w /src emscripten/emsdk:3.1.74 make -f Makefile.js   # dist/wasm/

On Linux or WSL a plain make builds ./temu (make USE_KVM=1 for KVM); turn off what you lack with CONFIG_SDL= or CONFIG_FS_NET=. Tests: make x86-selftest, sh tests/x86_jit_test.sh and make inflate-test; CI runs them on every push. See AGENTS.md for the source map and the engine's rules.
